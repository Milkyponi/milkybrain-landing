How a build gets opened

  1. Open the build container

    Unreal IoStore v11, REDengine, Unity, LÖVE2D or a studio's own engine. The build is read where it ships, and no string leaves it for a spreadsheet.

  2. Translate every string, glossary locked

    Dialogue, interface, tooltips, item text. One word is fixed for one thing before the first string is written, and the file ships with the work.

  3. Repack the build, then play it

    The files go back into the container they came from and install natively. We play the running game at 1280×720 and 1920×1080, and the captures go out with the files.

Which files should I send?

For the audit, the store link and the public build. For a sprint, the text container as it ships, or an exported string table if you already have one. If pulling the strings out is the problem, that is part of the work.

How long does a full game take?

Audit in 48 hours. Demo sprint in 7 days for up to 5,000 words. Full game in 14 to 21 days. The clock starts when the deposit lands.

Do you sign an NDA for the build?

Yes, before any file changes hands. The first audit needs no NDA, because it only reads the build everyone can download.

Who translates the strings?

An agent system built in-house does the volume. One person sets the glossary, reads every string in context and signs off the final pass.
